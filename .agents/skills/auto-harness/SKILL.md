# Auto-Harness 专家组决策与执行引擎

## 触发时机
当用户提出“需要规划下一个迭代”、“有多个技术方案需要决策”、“不知道该从哪里开始”或明确要求“组建专业团队投票”时，Agent 应主动调用此 Skill 的逻辑。

## 执行流程

1. **需求分析与角色定义 (Analysis & Persona Definition)**
   主 Agent 根据当前项目的上下文（如 `PROGRESS.md`, `ARCHITECTURE.md`）总结出目前面临的几个候选项（如 Bug修复、功能A、功能B）。
   根据任务特性，定义 3 个不同的专家角色，例如：
   - `架构师 (Architect)`：关注系统可扩展性、重构成本、长期价值。
   - `产品经理 (Product Manager)`：关注用户体验、交付速度、可用性。
   - `安全工程师 (Security/DevOps)`：关注稳定性、无 Bug 率、部署便利性。

2. **自动拉起讨论组 (Subagent Invocation)**
   使用 `invoke_subagent` 工具，同时拉起上述定义的 3 个专家 Subagent。
   将候选项清单发送给他们，要求他们基于各自的专业视角：
   - 分析每个选项的优劣。
   - 给出一个明确的**优先推荐项 (Vote)**。

3. **收敛与表决 (Voting & Decision)**
   主 Agent 汇总所有专家的返回结果，进行计票。
   如果存在平局或分歧较大，主 Agent 负责综合评判，给出最终决定，并向用户公示投票结果和决策理由。

4. **自主推进与闭环 (Autonomous Execution)**
   决策一经作出，主 Agent 无需等待用户二次确认（用户仅负责提需求和验收），直接进入执行阶段：
   - 修改对应的代码文件。
   - 运行 `.harness/verify.sh` 或相关测试。
   - 如果测试失败，自主查阅报错并修复。
   - 直到所有测试通过，任务完成，最后才向用户汇报验收标准。
