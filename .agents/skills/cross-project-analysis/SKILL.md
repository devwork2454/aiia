# Cross-Project Analysis (跨项目比对与迁移评估)

## 🎯 目的
提供标准化工作流，用于在两个不同代码库（或项目）之间执行深度对比、识别架构与依赖异同，并对代码迁移或融合操作进行可行性与风险评估。

## 适用场景
- 用户需要将某个功能模块从「项目A」迁移到「项目B」前，请求进行可行性评估。
- 用户需要比对两个相似开源项目，或同一项目的两个差异较大的分支/版本。
- 需要梳理两套代码的依赖冲突、API 不兼容点或底层架构差异。

## 🛠️ 标准工作流 (Workflow)

1. **环境与输入确认**
   - 确认项目 A（源项目）和项目 B（目标项目）的绝对路径。
   - 明确用户需要比对的范围（全量比对、特定模块、或特定的基础库）。

2. **架构与依赖对比**
   - **依赖文件比对**：读取并比对 `package.json`, `requirements.txt`, `go.mod`, `pom.xml` 等依赖清单，分析核心库版本冲突。
   - **目录拓扑比对**：获取两边的顶层或指定模块层级的目录结构，寻找对应关系的模块。

3. **核心逻辑深入分析**
   - 聚焦用户关心的核心逻辑代码文件，提取关键类、接口定义及核心算法。
   - 分析代码风格、设计模式以及运行时的前置条件差异。

4. **产出评估报告**
   - 整理并输出结构化的评估报告（Markdown 格式），内容须包含：
     - **概览**：两个项目/模块的整体异同总结。
     - **依赖与架构冲突**：详细列出版本不兼容或架构不匹配的点。
     - **迁移/重构建议**：按步骤列出如何进行迁移，如何适配接口。
     - **风险点预警**：指出可能需要手动介入或深度重构的高风险区域。

## ⚠️ 注意事项
- 处理大仓库时避免全量读取，应利用 `grep_search` 或精准查看文件的方式进行分析，防止上下文溢出。
- 严格遵循 AIIA Agent Response Guidelines，汇报时需要条理清晰，使用序号明确决策项。
